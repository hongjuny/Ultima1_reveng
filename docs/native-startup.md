# 네이티브 macOS 초기화 화면

로컬 산출물은 `build/Ultima I.app`이다. [빌드·실행 안내](../macos/README.md)에 따라
실행하면 Origin 로고, 성·호수·밤하늘의 인트로 애니메이션, Ultima I 타이틀을
순서대로 보여 준다. 네이티브 타이머가 장면을 진행하고 완성된 타이틀에서 멈춘다.
Return으로 타이틀까지 건너뛰고 Command-R로 처음부터 재생할 수 있다.

## 원본에서 네이티브 코드로의 대응

| 원본 단계 | 구현 |
| --- | --- |
| `U1.SYSTEM` 시작 파일 선택·ProDOS 로드 | 네이티브 앱이 번들 내 `U1.INTRO`를 `$0800`에 로드한다. 원래 ProDOS 자체의 실행은 macOS 파일 로드로 대체한다. |
| `U1.INTRO $0800 → $0F23` | Ghidra에서 생성한 주소별 Swift 블록으로 진입한다. |
| `$0F28 → $B70C`, 인라인 `MAKE.INDATA` | 호스트 로더가 인라인 이름을 소비하고 파일을 `$1E00`에 로드·실행한 뒤 carry-clear 반환 계약을 적용한다. |
| `MAKE.INDATA $1F17` | 원본 페이지 복사·압축 해제 코드를 번역 실행한다. `$2000–$27FF → $8700–$8EFF`, `$27BD–$4DBC → $6000–$85FF` 복사가 유지된다. |
| 재배치 코드 `$8700–$8762` | 원래 저장 주소와 별도로 Ghidra 프로그램 `INTRO.RELOC`을 `$8700`에 가져와 번역한다. |
| `U1.INTRO` 화면 구성·애니메이션 | 그림 데이터의 읽기, 화면 주소표, 직접 메모리 쓰기, 자기 수정 피연산자와 분기를 주소에 대응시켜 실행한다. |
| HGR 페이지·Apple II 소프트 스위치 | Swift 메모리 버스와 [CoreGraphics 렌더러](../macos/Sources/HGRRenderer.swift)로 대응한다. |
| 바쁜 대기 `$1F46`, `$0E23` | 대기 루틴의 종료 레지스터·플래그 상태를 적용하고 네이티브 타이머로 표시 시간을 정한다. 원본의 사이클 단위 시간 일치는 주장하지 않는다. |

[시작 전용 Ghidra 분석](../tools/ghidra/export_startup.py)은 기존 전체 프로젝트와
별도인 비공개 `build/macos-startup/Startup.gpr`를 만든다. 현재 입력은
`U1.INTRO` 858개, `MAKE.INDATA` 259개, `INTRO.RELOC` 54개로 합계
**1,171개 명령 후보**다. [번역 생성기](../tools/transcribe_startup.py)는 각 명령의
원본 바이트를 추출 파일과 대조하고 페이지별 Swift 함수를 만든다. 원본 주소를
키로 실행하며 미번역 PC·예상하지 않은 opcode 변경은 오류로 남긴다.

이 과정에서 실제로 두 종류의 빈칸이 드러났다. `$0A5E`의 JSR은 실행 중 RTS로
바뀌므로 그 변경을 명시적으로 처리했다. `$0D9B/$0D9E`는 BIT 명령의 피연산자와
겹친 LDA 진입점이다. Ghidra의 `PseudoDisassembler`로 두 대체 진입점을 따로
내보내어 본래의 경로와 함께 번역했다. 전체 파일을 한 줄씩 명령으로 가정해서
메운 구간은 없다.

## 시작 화면의 수용 기준과 검사

타이틀 유지 시점은 실제 애니메이션의 `PC=$0B23`, `$09DD=4`, `$09DF=$88`이다.
이때 Ultima 로고와 검이 화면에 완전히 표시된다. 원본의 이후 퇴장·디졸브 대신
네이티브 시작 화면으로 이 프레임을 유지한다.

[대조 도구](../tools/verify_native_startup.py)는 실제 빌드된 앱을 창 없이 실행하여
초기화 결과를 얻는다. 앱은 로컬 원본 두 파일을 직접 로드하며 에뮬레이터나 저장
스냅샷을 실행 의존성으로 사용하지 않는다. 비교 대상만 별도로 확보한 원본
스냅샷·참조 실행이다.

| 비교 시점 | 독립된 원본 근거 | 검사 |
| --- | --- | --- |
| Origin 로고 완성 | 기존 `intro-support` 스냅샷 | 두 HGR 페이지 총 16,384바이트 일치 |
| 첫 인트로 키 검사 | 기존 `intro-key-ready` 스냅샷 | 준비된 성·호수 장면과 표시 페이지를 포함한 두 HGR 페이지 일치. 이 최초 검사에서는 아직 Origin 페이지가 표시된다. |
| Ultima 타이틀 유지 | 조건부 중단점과 지연 루틴만 축약한 원본 실행 | 두 HGR 페이지 일치, 타이틀 장면의 활성 페이지 `$2000` 일치 |

세 시점에서 **그래픽 메모리 49,152바이트**, 각 활성 페이지의 네이티브 렌더 결과
**322,560픽셀**이 원본 메모리로부터 독립적으로 계산한 결과와 일치했다. 빌드 입력과
실행 파일의 해시도 검사하므로 수정 전의 앱으로 검증이 통과하지 않도록 했다.
참조 실행의 유일한 코드 개입은 `$0E23`의 지연 루틴을 `A=0,C=1,V=0`의 같은
종료 상태로 축약한 것이다. 타이밍·실제 오디오 출력은 이번 화면 수용 기준에
포함하지 않는다.

AppKit 창, 재생 메뉴·도구 막대, 전체 화면과 화면 비율 보존을 구현했고 로컬
번들의 컴파일·서명 검사를 통과했다. 현재 도구 환경에서는 macOS의 앱 등록 단계가
차단되어 실제 창 표시 테스트를 마치지 못했다. 창 없는 네이티브 실행과 픽셀
대조는 완료했다. 원본 데이터·생성된 코드 목록·이미지·앱은 모두 `build/`에만 둔다.

다음 구현 단위는 타이틀 입력에서 `MI.U1 → STUPH → GEN`으로 이어지는 초기 메뉴다.
이번 산출물의 게임 기능 범위는 시작 화면까지다.
