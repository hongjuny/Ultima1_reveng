# 실행 시점별 메모리와 제로 페이지 수명

제로 페이지 `$0000–$00FF`를 게임 전체에 적용되는 하나의 구조체로 취급할 수 없다. 같은 주소가 모듈과 호출 깊이에 따라 좌표, 지도 포인터, 전투 임시값, 가격으로 다시 쓰인다. 아래의 `실행`은 같은 계보의 비공개 스냅샷 비교, `바이트`는 원본과 재조립 일치, `Ghidra 후보`는 자동 분석의 참조를 뜻한다. 주소와 그 주소에 들어간 값은 구분한다.

## 로드 시점과 보존 영역

| 시점 | 주요 상주 영역 | 메모리·제로 페이지 결과 |
| --- | --- | --- |
| 시작 | `U1.SYSTEM $2000`, 이어 `U1.INTRO $0800`와 `MAKE.INDATA $1E00` | 뒤의 `STUPH $0800`과 주소가 겹친다. 시작 단계의 `$0800` 코드를 게임 중 입력 서비스로 해석하면 안 된다. |
| 공용 엔진 준비 | `MI.U1 $7000–$89BC`, `STUPH $0800–$1FFF` | `MI.U1`의 `$8956–$89BC` 초기 로더 꼬리는 오버레이가 올라오며 교체된다. |
| 게임 장면 | `MI.U1 $7000–$8955`와 `STUPH`; `GEN/OUT/CAS/TWN/DNG/SPA/TM` 중 **하나**가 `$8956`부터 | `$7E6D–$8036` 플레이어 기록은 장면 사이에 유지된다. `$00/$01` 같은 제로 페이지 임시값은 장면 진입 시 다시 해석하거나 덮어쓴다. |
| 지도·그림 교체 | 야외 지도 `$6000`; 실내 `TCMAPS` 작업본 `$B400`; 성 글리프는 `$B000↔$0800` 교환 | 해당 순간에 어느 파일이 상주하는지가 코드·데이터 분류와 포팅 상태 수명을 결정한다. [메모리 수명 표본](turn-contracts.md#메모리-수명-표본) 참조. |

## 제로 페이지에서 확인된 관계

| 주소 | 시점별 용도와 근거 | 포팅 모델 |
| --- | --- | --- |
| `$00/$01` | `OUT`, `CAS`, `TWN`의 현재 장면 X/Y. `CAS` 진입에서 `(30,31)→(0,9)`, `TWN`에서 `(29,32)→(19,17)`을 **실행** 확인. `DNG` 진입에서는 야외 `(43,15)`를 유지하고 던전 로컬 좌표는 `$A4E8/$A4E9=(1,1)`로 따로 시작한다. | 야외·성·마을 좌표를 하나의 전역 X/Y로 묶지 않는다. 던전은 별도 좌표계를 둔다. |
| `$0C/$0D` | [성 이동 코드](../disasm/CAS-move-check.s)는 `$00/$01`과 방향을 합쳐 후보 X/Y에 쓰고, [확정 코드](../disasm/CAS-move-commit.s)는 통과 뒤 이를 `$00/$01`로 옮긴다 (**바이트**). 성·마을 첫 입력 스냅샷에서는 야외 진입 좌표가 이 자리에 남아 있다 (**실행**). `OUT`에도 다른 사용처가 있다. | 호출/장면별 임시값으로 취급하고 영속 좌표로 저장하지 않는다. |
| `$24/$25` | `MI.U1`의 [문자 출력](../disasm/MI.U1-text-control.s)이 `$24`를 전진시키고 행 전환 코드 `$8089`가 `$25`를 증가시킨다. `STUPH $1A1D`도 이 둘을 읽는다. 각 실내 첫 키 폴에서 `(01,17)`로 재설정된 것을 **실행** 확인. | 텍스트 표시 커서의 열/행 후보. 화면 영역·줄바꿈 전체 규칙은 추가 검증한다. |
| `$72/$73` | [야외 타일 조회](../disasm/OUT-tile-lookup.s)에서는 `$6000+Y×64+X`를 가리키는 포인터. [성 배우 탐색](../disasm/CAS-actor-lookup.s)에서는 비교할 X/Y, 성 전투에서는 명중·피해 임시값. [마을 식량 구매](../disasm/TWN-food-purchase.s)에서는 16비트 가격. 각각 **바이트** 일치. `STUPH`도 자체 화면 작업에서 같은 주소를 사용한다. | 이름 하나를 전역 필드로 붙이지 않는다. 함수 인자/스크래치의 수명을 호출 경계로 제한한다. |
| `$74–$77`, `$78` | `STUPH $1D64–$1D7E`가 키보드 `$C000`을 읽어 4바이트 버퍼에 넣고 `$78` 길이를 갱신하며 `$C010` 스트로브를 지운다 (**바이트**). | 입력 버퍼는 게임 명령 해석 전의 I/O 상태다. 키 래치 타이밍·소비 루틴 차이는 아직 열려 있다. |
| `$AA–$AD` (`SPA`), `$C3/$C4` (`TM`) | Ghidra가 각각 여러 참조를 찾았지만 함수 경계와 의미를 아직 검증하지 않았다. | 현재는 **Ghidra 후보**로만 기록한다. 이름·수명을 임의로 정하지 않는다. |

`$7E73/$7E74`는 제로 페이지가 아니라 **플레이어 기록 안의 야외 복귀 좌표**다. 성·마을·던전 첫 입력에서 각각 `(30,31)`, `(29,32)`, `(43,15)`를 유지했다. 또한 던전 생성기의 시드 바이트는 제로 페이지 `$72/$73`이 아니라 **`$A504/$A505`**에 있다. 첫 층에서 관찰한 `$72,$3C`는 이 두 주소의 **값**이다. [던전 생성 근거](dungeon-map.md#first-generator-seed)를 참조한다.

[오버레이 제로 페이지 검증기](../tools/verify_zero_page_lifetimes.py)는 `OUT→CAS`, `OUT→TWN`, `OUT→DNG`의 스냅샷 계보와 위 좌표 값을 확인한다. 이 스냅샷은 각 장면의 첫 입력을 보여주며 모든 중간 쓰기를 기록한 것은 아니다. `CAS`·`TWN`의 첫 Up 턴에서 `$0001,$000C,$000D,$0072,$0073`가 두 장면 모두 바뀐 사실과 값 비교는 [한 턴 계약](turn-contracts.md)에 있다.

## Ghidra의 코드·데이터 분류는 출발점

검증된 진입점·간접 주소표 대상·공용 벡터로 보강한 Ghidra 12.1.4 분석에서 아래처럼 분류됐다. 각 행의 세 바이트 수를 합하면 해당 파일 길이다. `명령`은 **후보 명령 바이트**, `정의된 데이터`는 **자동 또는 수동으로 지정한 데이터**, `미분류`는 **아직 결정되지 않은 바이트**다. 어느 열도 원본 게임의 참된 코드/데이터 경계를 단독으로 증명하지 않는다. 검증된 것과 후보를 따로 분할한 [파일별 장부](code-data-ledger.md)를 함께 읽는다.

| 파일 | 명령 후보 | 정의된 데이터 | 미분류 | Ghidra의 제로 페이지 참조 |
| --- | ---: | ---: | ---: | ---: |
| `U1.SYSTEM` | 75 | 9 | 1,598 | 7 |
| `U1.INTRO` | 1,854 | 60 | 555 | 132 |
| `MAKE.INDATA` | 501 | 1 | 13,375 | 115 |
| `MI.U1` | 1,045 | 269 | 5,275 | 59 |
| `STUPH` | 1,806 | 32 | 4,306 | 198 |
| `GEN` | 1,007 | 706 | 7,219 | 30 |
| `OUT` | 2,195 | 539 | 2,496 | 157 |
| `CAS` | 1,892 | 1,452 | 2,180 | 114 |
| `TWN` | 1,562 | 1,175 | 5,724 | 94 |
| `DNG` | 2,288 | 788 | 6,975 | 10 |
| `SPA` | 1,654 | 852 | 7,424 | 138 |
| `TM` | 2,216 | 580 | 5,327 | 208 |

`MI.U1`의 [공용 키 26개](command-dispatch-matrix.md), 여섯 오버레이의 16비트 핸들러 주소 156개, 재조립이 일치하는 인라인 인자와 방향표 68바이트를 Ghidra에서 데이터로 명시했다. 각 포인터의 Ghidra 해석 결과를 추출 파일의 2바이트 값과 모두 대조했다. 표의 `정의된 데이터`에는 이처럼 수동으로 지정한 범위가 포함된다.

처음에는 검증된 어셈블리 3,191바이트 중 Ghidra가 1,480바이트만 명령으로 표시했다. 검증된 조각의 시작 주소만 주었을 때는 3,081바이트를 표시했지만, 일부 인라인 데이터를 명령으로 잘못 읽었다. 인라인 범위를 지정하고 간접 핸들러·벡터의 진입점을 추가한 현재 분석에서는 [검증 코드 3,980바이트와 검증 데이터 406바이트](code-data-ledger.md)가 각각 명령과 데이터로 분류된다. **이것도 코드 커버리지가 아니다**: 검증 구간 밖의 자동 명령은 인라인 문구·그림 데이터를 오독했을 수 있다. [어셈블리 주소표](assembly-atlas.md)와 [Ghidra 호출 지도](ghidra-call-atlas.md)를 대조해 함수 경계를 계속 교정한다.

개인 Ghidra 프로젝트와 TSV는 `build/ghidra-project/`에 둔다. [메모리·제로 페이지 추출기](../tools/ghidra/ExportUltimaMemory.java), [일괄 실행 도구](../tools/ghidra/import_modules.py), [결과 검증기](../tools/ghidra/verify_exports.py)가 재현 경로다. 바이너리나 대량의 자동 역어셈블 출력은 Git에 넣지 않는다.
