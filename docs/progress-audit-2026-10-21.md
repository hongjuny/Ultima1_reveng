# 진행·투입 효율 점검 (2026-10-21)

대상은 1986년 Apple II ProDOS판 *Ultima I*의 동작 분석과 충실한 macOS 포팅 명세다. 이 문서는 현재 저장소와 로컬 검증 결과를 기준으로 한 계획 점검이며, 추정 시간을 실측 생산성으로 취급하지 않는다.

## 확인 가능한 성과

| 지표 | 현재 값 | 해석 |
| --- | ---: | --- |
| 검토·재조립 후 원본과 일치한 어셈블리 | 75개 조각, 2,603바이트 | 선택한 주소의 바이트 근거. 기능 완성률이 아님 |
| 로컬 통합 점검 | 65개 구간 통과, `PENDING` 0 | 현재 작업 공간의 비공개 이미지·스냅샷을 사용한 결과 |
| 추적 스크립트 / 검증 스크립트 | 88개 / 62개 | 자동화 자산인 동시에 유지 비용 |
| 로컬 추적 보고서 | 246개 | 통제 실험과 반복 실행 포함. 고유 게임 규칙 246개를 뜻하지 않음 |
| 커밋 | 92개 | 2026-10-20 첫 커밋부터 약 20시간의 경과 시간. 집중 작업 시간이나 토큰량을 뜻하지 않음 |

게임 파일 15개의 합계는 103,376바이트이며, 검토된 어셈블리 2,603바이트는 단순 크기 비율로 약 2.5%다. 원본에는 코드·데이터·빈 공간이 섞여 있고 조각은 핵심 경로에서 선택했으므로 **2.5%를 분석 완료율로 사용하지 않는다**. 반대로 자동 검증 통과만으로 미관측 분기가 해결된 것도 아니다. 이 세션의 정확한 토큰 사용량과 비용은 저장소에서 측정할 수 없다.

시작부터 `U1.SYSTEM → U1.INTRO → MI.U1 → GEN → OUT`으로 이어지는 로드와 캐릭터 생성·저장·불러오기, `CAS`/`TWN`/`DNG` 진입을 재현했다. 성의 경비병·사망/부활, 마을 식량 구매, 던전의 1–3층 생성·이동과 일부 몬스터 이동·전투·사망을 주소, 메모리 상태, 입력 시퀀스로 검증했다. 바이너리와 비공개 추적물은 Git에서 제외했다.

## 효율 평가

초기의 추출 검증, 에뮬레이터 제어, 스냅샷과 재생 도구, 바이트 일치 검사에 쓴 노력은 가치가 컸다. 이 기반 덕분에 저장 실패, 디스크 헤드 위치, 특정 입력의 상태 변화처럼 정적 읽기만으로 놓치기 쉬운 동작을 확인했다. 확인한 개별 경로의 **증거 강도는 높다**.

최근 방식은 한 입력·한 주소·한 경계값마다 스크립트와 커밋을 늘려 범위 확장 속도를 떨어뜨린다. `tools/` 159개 파일과 긴 분석 로그에 비해 모듈별 상태 표, 명령 표, 전체 경로의 빈칸은 여전히 크다. 따라서 **증거 강도와 전체 범위는 다르다**. 이 방식만 계속하면 토큰과 시간이 많이 들면서 포팅 준비 시점은 늦어진다.

## 남은 핵심 범위

| 분야 | 현재 빈칸 | 우선순위 |
| --- | --- | --- |
| 게임 완주 경로 | `SPA`·`TM`의 실행 시나리오와 승리 조건이 없음. 두 모듈의 검토·재조립 조각도 없음 | 최상 |
| 일반 규칙 | `GEN`의 다른 선택지, `OUT`의 지형·이동수단·전투·상태, `TWN`/`CAS`의 상점·NPC·퀘스트, `DNG`의 함정·보물·깊은 층과 특수 몬스터 | 높음 |
| 데이터·상태 | 플레이어 기록의 필드 스키마, `NIF`·`MAPCHARS`·`STUPH`·`TCMAPS`의 의미와 소비자, 저장 갱신 시점이 불완전함. `TCMAPS` 마지막 복사의 4바이트 초과 읽기도 미해결 | 높음 |
| 표시·입출력 | 화면·색·소리·키 반복·프레임 타이밍의 비교 기준과 macOS 차등 테스트가 없음 | 높음 |
| 분석 기반 | 도달 가능한 코드/데이터의 파일별 분류와 호출·상태 의존 관계가 불완전함. 원본 `.woz`는 현재 에뮬레이터에서 ProDOS 오류가 나며 블록 동등 `.po`로 추적 중 | 중간 |

현재는 **검증된 일부 경로를 포팅하기 시작할 수 있는 상태**다. 게임 전체를 원작에 충실하게 구현·판정할 명세가 갖춰진 상태는 아니다. ProDOS 내부 전체를 역어셈블할 필요는 없지만, 게임에서 관찰되는 호출 결과는 확인해야 한다.

## 재조정한 작업 방식

1. **증거 장부를 만든다.** 모듈·명령·분기마다 정적 추론, 바이트 일치, 실행 관측, 저장 왕복, 화면/소리 비교를 별도 칸에 표시한다. 주소, 입력, 스냅샷 계보, 미해결 조건을 연결하고 파일별 미분류 범위를 집계한다. 현재 체크가 비공개 스냅샷을 전제로 하는지도 명시한다.
2. **완주 경로의 구멍을 먼저 닫는다.** 기존 캐릭터 상태를 이용해 `OUT → SPA → TM → 승리`의 최소 실행 경로와 실패 경로를 확보한다. 필요한 `DNG`·`CAS`·`TWN` 전제 조건을 역으로 조사한다. 이 경로가 확보되기 전에는 이미 검증한 던전 근접 분기를 무한히 확장하지 않는다.
3. **시나리오를 작업 단위로 묶는다.** 기존 스크립트를 버리지 않고 입력, 체크포인트, 상태 비교를 선언형 시나리오로 묶는다. 한 명령의 정상·경계·실패 입력을 한 번의 분석 묶음으로 처리하고, 산출물은 명령 표·상태 필드·필요한 어셈블리·재생 검증을 함께 남긴다.
4. **데이터 추출과 포팅 비교를 병행한다.** 지도·문자·테이블은 구조/소비자/왕복 검증으로 정리한다. 화면·소리·저장 결과의 기준 장면을 확보하고 macOS 구현이 같은 입력을 재생할 수 있게 한다.

다음 측정 단위는 커밋 수나 어셈블리 바이트가 아니라 **새로 설명된 명령·분기와 상태 필드, 재현된 완주 경로, 미해결 항목 감소**다. 두 작업 묶음 뒤 실제 처리 시간을 기록해 아래 예산을 갱신한다.

## 남은 시간의 계획 예산

| 성과물 | 추가 집중 작업 시간(가정) | 완료 판정 |
| --- | ---: | --- |
| 증거 장부·시나리오 묶음화, `SPA`/`TM` 첫 실행 경로 | 30–60시간 | 커버리지 빈칸이 보이고 두 모듈의 입력·로드·상태를 재현 |
| 시작부터 승리까지의 주요 규칙과 데이터 구조 | 추가 100–200시간 | 주요 명령과 전제 조건, 데이터 참조, 저장/재시작 경로가 검증됨 |
| 원작 충실도용 경계값·대체 경로·표시·소리·타이밍 | 추가 150–300시간 | 로드맵의 포팅 준비 수용 기준 충족 |
| macOS 구현과 원본 대조 | 별도 150–300시간 이상 | 같은 시나리오의 상태·표시·저장 차이가 설명됨 |

따라서 **포팅 준비 명세까지 280–560시간**, macOS 구현·대조까지는 그 이상이 임시 예산이다. 주 20시간의 집중 작업이면 명세만 약 14–28주다. 기존 커밋 속도나 2.5% 바이트 비율을 선형 외삽한 수치는 아니다. `SPA`/`TM`과 데이터 형식의 미지수가 커서 오차도 크며, 첫 완주 경로 후 다시 추정한다. 빠른 시제품은 그보다 일찍 가능하지만, 이를 충실도 완료로 표시하지 않는다.

구체적인 완료 기준은 [포팅 로드맵](porting-roadmap.md), 근거의 구분은 [충실도와 증거](porting-fidelity.md)에 둔다.
