## 모듈을 가로지르는 세 경로

1. **키 입력:** 하드웨어 `$C000/$C010` → `STUPH` `$1D64`와 입력 벡터 → `MI.U1` `$827D/$82A2` → 오버레이별 핸들러 표. `OUT`은 `$15C5 → $1DA3`, `CAS`/`TWN`/`DNG`/`SPA`는 `$15C2 → $1D97`을 사용한다. [재조립된 분기](../disasm/STUPH-input-dispatch.s)는 둘이 `$1DAD`의 큐 소비·정규화 코드로 합류함을 확인한다. `TM`은 `$9815/$9827`에서 `$15C8/$15BF`를 조합한 뒤 `$82A2`에 연결된다. 여섯 모듈의 첫 명령이 각자 다음 입력으로 돌아오는 흐름은 [실행 비교](turn-contracts.md)로 확인했다. 하드웨어 키 래치의 실제 폴 간격과 키 반복은 미측정이다.
2. **화면 표시:** 오버레이 루프/핸들러 → `MI.U1` `$836E` 상태 표시 또는 `$8119` 인라인 문구 해석 → `$8037` 바이트 읽기 → `$8068` 제어문자 해석 → `$8062` 일반 문자 출력 → `STUPH` `$15B0 → $1A1D`와 다른 화면 벡터 → `$1200/$12C0` 행 주소표 및 `$2000/$4000` 화면 페이지. `MI.U1`의 인라인 문구·문자 경로 91바이트는 재조립 일치한다. 아래 야외 재생은 한 문자에서 실제 화면 메모리 변경도 확인했다. 지도의 타일→픽셀 변환, 실제 색·페이지 전환은 아직 실측하지 않았다.
3. **파일 전환:** 오버레이가 `MI.U1` `$88FD`에 선택값 전달 → `STUPH` `$1589`와 ProDOS 호출 → `$8956`의 기존 코드 교체 → 새 오버레이 엔트리. 로더의 정상 경로는 `GEN`·`OUT`·`CAS`·`TWN`·`DNG`에서 관측했다.

소리는 `$C030` 토글이 `STUPH`의 `$1Bxx`에서 확인되는 단계다. 어떤 게임 이벤트가 어느 소리 루틴을 호출하는지, 피치와 길이가 얼마나 되는지는 아직 표에 넣을 수 없다. 이 빈칸은 대표 입력 한 번을 끝까지 추적하면서 채운다.

## 첫 출력 경로 실행 관측

`OUT`에서 Space 명령을 마친 기존 스냅샷을 재생했다. `$8995 → $8119 → $8062 (A=$0E) → $15B0 → $1A1D → $8065 → $89A1 → $836E → $8A6C` 순서로 멈췄다. `$8062` 직전과 `$8065`에서 메인 RAM `$2000–$5FFF`를 비교하니 **12바이트**가 달랐다. 변경 주소는 `$27D0,$2BD0,$2FD0,$33D0,$37D0,$3BD0,$47D0,$4BD0,$4FD0,$53D0,$57D0,$5BD0`이다. [추적 스크립트](../tools/trace_out_render_pipeline.py)와 [검증기](../tools/verify_out_render_pipeline.py)는 비공개 스냅샷의 계보, CPU 체크포인트, 변경 주소를 확인한다.

`$8062`와 `$8065`의 에뮬레이터 프레임 번호·픽셀 버퍼 해시는 같았다. 다음 `$8A6C` 입력 지점에서는 프레임 번호가 2834→2835로 증가하고 픽셀 버퍼 해시도 달랐다. 따라서 **글리프 루틴의 화면 메모리 쓰기와 다음 프레임의 변화**를 각각 관측했다. 그 픽셀 차이 전체가 이 한 글리프 때문인지는 아직 분리하지 못했고, 색·페이지 선택도 미확인이다.

성 지도 표시에서는 `MAPCHARS` 1,024바이트가 평소 `$B000`에 있다가 `$9B6E` 교환 루틴으로 `$0800`에 올라온다. 첫 지도 글리프는 `STUPH` `$1A58`의 `LDA $0800,Y`를 실행했고, 표시 후 글리프 데이터는 `$B000`으로 돌아왔다. 파일은 128개 코드 × 8개 스캔라인 평면으로 정확히 왕복한다. [데이터 형식과 실행 근거](../disasm/MAPCHARS.md)를 별도 문서에 정리했다.

첫 성 지도 글리프 `$40`만 바꾼 대조 실행은 비디오 RAM 8바이트와 프레임의 14×8 영역을 정확히 분리했다. `$FF` 8개 스캔라인은 흰색 112픽셀, `$80`은 검은색이었고, 비트 0과 6의 단독 패턴은 각 행의 왼쪽·오른쪽 2픽셀을 밝혔다. 이 장면에서는 상위 비트만 바꿔도 화면은 같았다. [픽셀 대조 기록](../disasm/MAPCHARS.md)에 주소·범위·제한을 적었다. 색상 전반과 다른 디스플레이 설정은 아직 확인하지 않았다.
