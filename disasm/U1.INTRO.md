# U1.INTRO

Load range: `$0800–$11A4`. Intro code and display data share this file.

| Address | Disassembly / evidence | Interpretation |
| --- | --- | --- |
| `$0800` | `JMP $0F23` | First entry and jump observed at runtime |
| `$0803` | `JMP $0F41` | Second entry |
| `$0B57` | `JSR $B70C`, followed by `MI.U1` at `$0B5A` | File request on this code path |
| `$0F23` | Clears `$03CE`; calls `$B70C` at `$0F28` | Runtime request of `MAKE.INDATA` confirmed |
| `$0F2B` | `MAKE.INDATA` inline filename | Argument to the preceding call |
| `$1039–$1056` | Polls `$C000`; on a key, clears strobe at `$C010` and calls `$0B50` | Intro key/timer loop |

The first entry at `$0800` reached `$0F23` in the private startup trace, with memory matching the extracted `U1.INTRO`. The next trace hit `$B70C`, returned at `$0F37` with carry clear, and reached `$0F41`. The loader executed `MAKE.INDATA`, whose copied payload ranges were verified in memory. The code retries while carry is set; that failure path remains untested. The second entry at `$0803` reaches `$0F41` and skips the request. A branch from `$1048` also enters `$0F41` after the input/timer loop expires.

At `$1051`, the key loop calls `$0B50` with the key code in A. `$0B50` compares it with `$9B`: that value enters a wait-for-next-key loop at `$0B61`; another value requests `MI.U1` through `$B70C`. The purpose of the `$9B` path and what the loader does after returning still need runtime confirmation.

Reviewed fragments: [entry vectors](U1.INTRO-entry.s), [key loop](U1.INTRO-key-loop.s), [MI.U1 request](U1.INTRO-load-mi.s), and [MAKE.INDATA request](U1.INTRO-load-support.s). All four reassemble byte-for-byte against the local extraction. Most of `$0807–$0F22` is display data mixed with code; its boundaries remain to classify.
