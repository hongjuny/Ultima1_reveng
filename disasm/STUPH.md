# STUPH — shared support and graphics

Load range: `$0800–$1FFF`. Early regions are patterned display data. Later regions contain executable support routines used by the common engine and overlays.

| Range | Disassembly / evidence | Interpretation |
| --- | --- | --- |
| `$1580–$1582` | Three-byte preface | Meaning open |
| `$1583–$15E8` | 34 consecutive `JMP` stubs, three bytes each | Callable interface; checked by `tools/inspect_stuph_vectors.py` |
| `$1583` | `JMP $177F` | First stub; callers in `MI.U1` |
| `$1586` | `JMP $1831` | Second stub |
| `$1589` | `JMP $1679` | Shared file-loader entry used by the `OUT` handoff |
| `$159E` | `JMP $19F3` | Called during module setup |
| `$15B9` | `JMP $1DF1` | Shared random-byte entry used by castle combat |
| `$15E3` | `JMP $1670` | Hardware support entry |
| `$15E6` | `JMP $1C15` | Last stub; omitted in the earlier 33-entry inventory |
| `$1DF1–$1E17` | [Reviewed 39-byte routine](STUPH-random.s), byte-matched | Mutates 16-byte state at `$1E18–$1E27`; returns byte at `$1E18` |
| `$1D64–$1D7E` | [Reviewed keyboard latch routine](STUPH-keyboard-latch.s), byte-matched | Reads `$C000`, buffers up to four high-bit key bytes at `$74–$77`, clears strobe through `$C010` |
| `$1D7E–$1DD5` | [Reviewed shared input dispatch](STUPH-input-dispatch.s), byte-matched | Bounded input and outdoor input converge on one queue-consumption and key-normalization path |
| `$1DD6–$1DF0` | [Reviewed input prelude](STUPH-input-prelude.s), byte-matched | Saves X/Y and cycles a self-modified display operand before either input path |
| `$1C39–$1D63` | [Reviewed outdoor raster](STUPH-outdoor-draw.s), byte-matched | Builds a 19×9 tile viewport, writes graphics rows, updates animation state, then falls into the keyboard latch |

The jump table makes this file an executable dependency, despite its graphics-heavy beginning. Next: identify each target routine and its callers without treating earlier image data as code.

The display path is now mapped at the static call level: `$15B0 → $1A1D` uses `$1200/$12C0` row-address tables and patches stores into the Apple II graphics pages near `$2000/$4000`. `$1592 → $193E` and `$1598 → $198F` also write those pages; `$15A1 → $19DC` sets drawing bounds. This identifies the resident renderer's main interface. One outdoor tile and one castle glyph now have controlled pixel observations; full glyph coverage, color mapping, and timing remain open. Speaker toggles at `$C030` occur in the `$1Bxx` support area, reached through sound-related vectors including `$15CB/$15D1`; their event semantics and timing remain open.

The [80-byte sound selector and table](STUPH-sound-dispatch.s) at `$1AB2–$1B01` reassemble exactly. `$15CB` enters `$1AC4`: A must be an **even value from `$00` to `$10`**, and `$1581` must be nonzero, for sound to dispatch. The nine table entries are return addresses one byte before the actual effect entries: `$00→$1BF4`, `$02→$1BEE`, `$04→$1BCE`, `$06→$1B4E`, `$08→$1BBD`, `$0A→$1B48`, `$0C→$1BA9`, `$0E→$1B32`, `$10→$1B42`. The code pushes the chosen address onto the 6502 stack and uses `RTS` to enter it, so an ordinary direct-call graph omits these nine edges. X is saved through `$69` and restored before entering the effect. `$1AF0` saves processor flags and disables interrupts around the effect. The `$1580/$175B` branch also changes `$C036` around dispatch; its hardware meaning needs separate verification.

The [48-byte queue code](STUPH-sound-queue.s) at `$1B02–$1B31` also reassembles exactly. `$15D1` enters `$1B02`, which shifts the pending bytes `$79–$7C` and plays the first through `$1AC4` when `$7D` is nonzero. `$15CE` enters `$1B19`, which stores A at `$79+X` and may call the dequeue routine when the count reaches its limit. The precise behavior when an existing tail byte is zero needs a runtime case; a simple four-item FIFO model would be premature. This identifies a stateful sound interface and its zero-page lifetime. Several effect routines below `$1B32` toggle `$C030`, sometimes with `$C0E8` reads and delay loops. Their pitches, cycle durations, and which game events enqueue each ID are not yet measured; the selector and queue byte match alone do not establish audible output.

The [22-byte pair of effects](STUPH-sound-two-pulses.s) at `$1B32–$1B47` also matches. ID `$0E` reaches a loop with Y=`$10`, A=`$30` and **16 `$C030` accesses**; ID `$10` reaches the same loop with Y=`$32`, A=`$17` and **50 accesses**. Each iteration calls `$1608` before toggling. These are exact program-loop counts, not audible pitches or elapsed times: the delay service and machine timing still need measurement. Ghidra now seeds all nine effect table targets as indirect entries, exposing candidate effect bodies without treating them as nine direct calls.

The bounded input stub `$15C2` jumps to `$1D97`, which calls `$1D7F` and in turn `$1D64`. `$15C5` jumps to `$1DA3`, the path used by `OUT`. At `$1D64`, a high-bit-clear read from `$C000` returns immediately. A high-bit-set key is appended to `$74–$77` while `$78<4`; the `$A0` value first resets `$78` to zero. An accepted key reads `$C010` to clear the keyboard strobe. Both the 27-byte latch and the following 88-byte dispatch fragment match the extracted file.

The two dispatch paths have different work **before** consuming a buffered key. `$1D97` calls `$1DD6`, then `$1D7F` polls `$1D64` up to seven times, calling `$160B` with `A=$4F` after an empty check. If the queue remains empty, it returns zero through `$1DCD`. `$1DA3` calls `$1DD6`, then `$1C39`, and tests queue length `$78` without that seven-iteration loop. The difference is established from [byte-matched control flow](STUPH-input-dispatch.s), while the first scene input paths are established by [runtime turn traces](../docs/turn-contracts.md). `$160B` is a nested count delay according to the local listing; its exact timing still needs measurement.

The outdoor `$1C39` renderer begins with map coordinates `($00−9,$01−4)` and stages 19 tile pairs in `$81–$A6` for each of nine rows. It reads world-map bytes through `$72/$73` from `$6000+64×row`, masks them with `$7E`, and replaces out-of-range positions with blank tile indices. Values `$20–$58` take an additional animation path using `$1769` and `$B700,X`; its visual meaning needs a tile-by-tile comparison. For each tile row, the code writes 16 scanlines, advancing the graphics source operand by `$60` per line. It patches the source operand at `$1CEB/$1CEC` and screen destination operand at `$1CEE/$1CEF`; the latter comes from `$1200/$12C0` row-address tables. After the ninth row, it updates animation counters and swaps pattern bytes, then falls through to the keyboard latch at `$1D64`. These are code and memory relationships from the [299-byte reviewed source](STUPH-outdoor-draw.s). A [controlled one-tile replay](../docs/outdoor-rendering.md) fixes one 28×16-pixel footprint and its sampled colors; the rest of the tile set remains open.

At the first `OUT` input poll, an unmodified emulator run reached `$1C39` at cycle 48,123,380 and returned to `$1DA6` at 48,254,297. Across that call, 5,362 bytes in `$2000–$5FFF` and 14 tile-pattern bytes in `$0C00–$0DFF` changed, while the `$6000–$6FFF` world map and `$1200–$13FF` row-address range stayed byte-identical. The frame advanced from 2825 to 2833 and its pixel hash changed. The `$0000–$00FF` scratch range changed at 42 addresses and `$1750–$178F` at four. This observation establishes a large display update inside the poll path; it does not assign every changed pixel to a particular world tile. [Private trace](../tools/trace_stuph_outdoor_draw.py) and [verifier](../tools/verify_stuph_outdoor_draw.py) retain the replay contract without publishing the snapshot.

The shared `$1DD6` prelude saves X/Y at `$1764/$1765`, calls `$1670`, then changes the operand at `$1DED` of its own `LDA #imm` before calling `$1A1D`. Static control flow makes the operand cycle `$7F,$7E,$7D,$7C` on successive calls; this is **self-modifying code**, not a data byte after the instruction. The visible effect of `$1670` and the display call here still needs a runtime comparison.

Both paths enter `$1DAD` when `$78` is nonzero. That code calls display routine `$1A1D` with `A=$20`, reads the first byte `$74`, decreases `$78`, shifts `$75–$77` down into `$74–$76`, maps `$FF` to `$88`, applies `EOR #$20` for values at least `$E0`, then masks with `$7F`. It restores X/Y from `$1764/$1765` and returns the normalized key in A. Consequently `$FF` becomes `$08` at return in this path. The full display effect, key timing, and repeated-key behavior still need runtime comparison.

The random-byte entry `$15B9` jumps to `$1DF1`. The routine starts with the byte at `$1E27`, accumulates it backward through state bytes `$1E26–$1E18` while preserving ADC carry, adds `$1E27` once more into `$1E18`, then increments the 16-byte state backward until the increment does not wrap. It returns the resulting `$1E18` byte. The [reviewed source](STUPH-random.s) reassembles exactly. A castle guard-hit replay returned `$9D`. In a separate controlled replay, changing only `$1E27` from `$A6` to `$59` immediately before the call made the routine return `$02`. The latter is a counterfactual branch test, not an unmodified gameplay observation; the [private verifier](../tools/verify_cas_guard_miss.py) checks that the two intervention snapshots differ in exactly that byte.

The `GEN`→`OUT` replay reached `$1589` after the selector copied `OUT` into `$7E16` and `$B736` copied it to the ProDOS filename buffer `$BA79`. In the saved runtime state, `$BF98 & $30 == $30`, so `$1679` built `/RAM/OUT` at `$1703` and called `$B71E` at `$16AD`. This lookup returned at `$16B2` with `A=$07`, carry set. Execution then reached `$16B9`, where another `$B71E` call uses the relative `OUT` string at `$1709`. A 15-second replay did not reach its `$16C8` return; it paused at `$D388` inside the disk driver's delay loop after about 122 million additional CPU cycles. The buffer at `$BA79` still held relative `OUT`, and the game disk was still mounted. The failure mechanism is not yet established. The a2m disk mount changed the simulated head position from quarter-track 2 to 38; `tools/trace_out_disk_attempt.py --preserve-head` tests that difference with a private snapshot copy.

The controlled replay changed only the two-byte Disk II quarter-track position from 38 back to the pre-swap value 2. The same relative `OUT` read then returned at `$16C8` with `A=$00`, carry clear (cycle 47,118,575); the loader returned at `$16FC` with carry clear and its caller resumed at `$892B` (cycle 47,623,376). All 5230 bytes at `$8956` match the extracted `OUT` file. This establishes the simulated head-position change as the trigger for the failed replay. It does not establish a game-code disk-read defect. The loader also attempted its `/RAM/OUT` cache path before returning; the cache outcome is not yet verified.
