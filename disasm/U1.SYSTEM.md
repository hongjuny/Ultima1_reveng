# U1.SYSTEM

Load range: `$2000–$2691`. ProDOS SYS startup file.

| Address | Disassembly / evidence | Interpretation |
| --- | --- | --- |
| `$2000` | `JMP $2088` | Startup entry |
| `$2007` | `U1.INTRO` string in startup header | Next program name |
| `$2088` | `SEI`; initializes ProDOS/display state and stack | Runtime entry verified from block-equivalent `.po`; exact handoff pending |
| `$21A6–$21AA` | `LDY $2006; BNE $21D6` | Runtime took `$21D6` with `Y=$08`; live header byte `$2006=$08` |
| `$21B4–$21D5` | `JSR $0100`; inline `Can't find a startup file.` text; `JMP $0133` at `$21D3` | Path taken when `$2006` is zero; runtime cause pending |
| `$21D6–$2222` | [Byte-matched startup handoff](U1.SYSTEM-startup-handoff.s) | Terminates the startup name, conditionally adjusts a ProDOS prefix, copies the name to `$02C0`, then jumps to `$0136` |
| `$2220` | `JMP $0136` | Runtime transfer reached `$0136`, then `U1.INTRO` `$0800` |

Code and inline display text are interleaved after `$2088`; the linear draft treats text as instructions. Earlier trace timeouts at PC `$21D4` cannot be mapped to this file: the source snapshot contained ProDOS bytes at `$2088`, so execution was still in ProDOS. A later block-equivalent `.po` boot verified the `U1.SYSTEM` header and entry bytes in memory at `$2088` and after snapshot restore. The subsequent runtime trace took `$21D6`, reached `$2220 → $0136 → U1.INTRO $0800 → $0F23`, and confirmed the intro entry bytes. The [reviewed fragment](U1.SYSTEM-startup-handoff.s) includes the ProDOS prefix branch and inline `$2047` argument at `$2212`; those optional branches are byte-matched but were not taken in this trace. The no-startup-file path is identified from extracted bytes only.
