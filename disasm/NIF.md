# NIF — ending image and scroll source

`NIF` is a 7,680-byte data file loaded at `$4000` by `TM $9052`. It contains **192 consecutive rows of 40 Apple II high-resolution graphics bytes**. Each byte contributes seven pixels in least-significant-bit-first order; the high bit is the HGR color-phase bit. A monochrome decode yields a 280×192 rasterized ending text screen. The picture and extracted pixel data stay under private `build/`; [the public extractor](../tools/extract_nif.py) writes `build/data/nif-monochrome.png` and a 7,680-byte phase plane `build/data/nif-phase.bin` locally. Recombining these two planes reproduces every original file byte exactly; `--check` verifies this without writing either artifact.

At `$9073–$9093`, `TM` moves 8,192 bytes from `$4000–$5FFF` to `$6000–$7FFF` and clears the former range. The file provides `$4000–$5DFF`; the other 512 bytes came from prior RAM. The [copy verifier](../tools/verify_tm_victory_gate.py) confirms this overlap. The animation at `$90AA–$9108` reads packed rows from **`$6000–$7DFF` only**. Its source pointer `$90E8/$90E9` starts at `$6000`, advances by `$28` after each row, and is `$7E00` when counter `$6D` reaches zero after 192 rows. The inherited `$7E00–$7FFF` tail is outside the row source. The program resets that pointer to `$6000` before the final key wait `$9132`.

The [render trace](../tools/trace_tm_nif_render.py) independently restored the post-copy state, matched the first row to the private file, and observed its 40 bytes copied to HGR address `$5FD0`, the bottom row of page 2. The next source was `$6028`. At the final key wait, **all 7,680 active HGR bytes on page 1 match `NIF` exactly** when indexed by the Apple II scanline address formula. The [verifier](../tools/verify_tm_nif_render.py) checks source ancestry, row steps, counter, first copy, and full final-page identity. This is an exact image-content contract for a macOS port; the animation timing, page flips, color artifact behavior, sound, and final text prompt still need separate presentation checks.

The [intermediate-frame trace](../tools/trace_tm_nif_frames.py) stopped at `$90FE` after each of the 192 row copies and sampled nine stages: 1, 2, 3, 16, 48, 96, 144, 191, and 192 rows. Odd copies write the page-2 bottom row at `$5FD0`; even copies write page 1 at `$3FD0`. At every sampled stage, the **write target page's bottom `n` HGR rows exactly equal the first `n` packed `NIF` rows** in top-to-bottom order. The alternate page may contain an older scroll frame. The emulator's latched video switches report `HIRES=1`, `TEXT=0`, `MIXED=0`, and the **opposite page displayed at `$90FE`**: odd copies find `PAGE2=0`, even copies `PAGE2=1`. On return from the `$90FE` call to `$15AD` at `$9101`, `PAGE2` has toggled to the just-written page at all nine samples. This directly confirms off-screen preparation followed by a page flip. [Verification](../tools/verify_tm_nif_frames.py) checks the source pointer, counter, page selection, and all sampled lower rows. Exact frame duration, artifact color, and any text or sound overlay require separate checks.

For zero-based row `y`, the HGR byte offset within an 8KB page is `((y & 7) << 10) | (((y >> 3) & 7) << 7) | ((y >> 6) * 40)`. The packed file instead uses `y * 40`. At the final frame, placing each packed row at this HGR offset reconstructs page 1 byte-for-byte. The local PNG extractor discards the phase bit and shows only monochrome geometry; it does not claim to reproduce composite color.
